## English

DSH Session Insights 0.8.0 adapts to DSH `0.2.2-rc.1` and raises the support floor to `>=0.2.2-rc.1`. Older hosts — the whole 0.2.0/0.2.1 lines and `0.2.2` prereleases below `rc.1` — are refused with no old-API fallback and no forward-support queue for retired hosts. The Node.js floor moves to `>=24.9.0`, matching the rc.1 host's own requirement, and the Cordis peer follows the rc.1 release family to `~4.1.0`.

### Changes

- The analyzer retargets its input identity to `0.2.2-rc.1` (`v4-dsh022rc1.1`). Semantic runs recorded by 0.7.0 or earlier no longer resume: finish them with the version that created them or start a new run; old runs and evidence are retained. Deterministic CLI caches move to version 10 and older entries are ignored automatically.
- Structured caller cancellation becomes its own settled outcome. The rc.1 tools pipeline classifies caller-cancelled calls with the structured error codes `ABORTED` / `ABORTED_BEFORE_DISPATCH` (`run_code` caller cancellation moved off `CODE_RUN_FAILED` in rc.1). Both analyzers count them in new `tool_execution.outer_cancelled` / `inner_cancelled` fields: never a success, never an execution failure, never an approval rejection, and never a claim that the call "did not run" — the call body reaches quiescence before the outcome settles, so side effects remain possible and the retained evidence says so. Contrast vectors keep cancelled, real-failure, approval-rejection and unknown-outcome classifications mutually distinct in both runtimes.
- The adaptation was verified against the real published rc.1 packages: the V4 vocabulary is unchanged from rc.5 (62 known event types, zero additions or removals), and official admission, session contract, repair-fixture and real Session/query/codec service checks run against exact rc.1. Fork/inheritance, job/team/workflow/context semantics and the privacy/resource boundaries carry over unchanged.
- Test and acceptance infrastructure converges on one current runtime: `tests/dsh-runtime` and `tests/dsh-host` pin exact `0.2.2-rc.1`; the retired `tests/dsh-*-rc5` trees and all their consumers (CI matrix, Windows workflow defaults, audit cohort, `.gitattributes`, README commands) are removed. CI runs the Node 24.9.0 floor on all three OSes plus one Node 25 probe of the same host.
- The stale marketplace entry (0.5.2-era DSH/Node claims) is refreshed to the 0.8.0 identity and the same floors.

### Known upstream dependency gap

The rc.1 packages (`dsh-commands`, `dsh-llm`, `dsh-agent`) still pin `zod@4.4.3` exactly ([GHSA-mrhx-c7xc-m3w5 / CVE-2023-54404](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5), patched in 4.6.6). This project's peer closure, the contract runtime tree and the host tree's exact-pinned nested copies resolve the vulnerable 4.4.3; the full host tree's top-level `zod` resolves to the patched 4.6.7. A fresh rc.1 production scan reports 18 affected package entries. We have not established a reachable DSH exploit path or measured everyday trigger probability.

The 0.7.0 exception expired with its cohort and was not renewed. On 2026-11-06 the maintainer made a new limited decision accepting this known risk for 0.8.0 and the exact reviewed rc.1 cohort: the bound manifest/lock/runtime/host-tree identities, the host queue, and the two reviewed 18-entry report graph variants. Acceptance does not mean the issue is fixed, unreachable or clean; it does not extend to new advisories or changed versions, dependencies or unreviewed graphs. The decision is event-bound with no calendar expiry or automatic monitoring. In local source checks, fresh production and full npm scans each exited 1 with 18 entries under the single advisory and were classified `accepted_known_risk`; these are local results, not exact-commit CI results. See the [risk and decision status](https://github.com/GreenLv/dsh-session-insights/blob/main/SECURITY.md#known-upstream-dependency-gap).

### Upgrade and validation limits

Upgrading a host below `0.2.2-rc.1` to at least `0.2.2-rc.1` is required before installing this candidate. Historical V4 session logs remain valid data input; old deterministic caches are ignored automatically and removing them is a separate deliberate cleanup. Update separately installed Python CLI/Skill consumers through their managed installer.

Development-stage verification covers this repository's applicable source and interface suites on the exact rc.1 runtime. Native dual-platform acceptance (installed-artifact, real-model, GUI and consumer-adoption checks on macOS and Windows), exact-commit CI, canonical artifact freezing and publication are later, separate gates owned by the release coordinator and are **not** claimed by this document.

## 简体中文

DSH 会话洞察 0.8.0 适配 DSH `0.2.2-rc.1`，并把支持下限提高为 `>=0.2.2-rc.1`。更旧的宿主——整个 0.2.0/0.2.1 线以及 `rc.1` 之前的 `0.2.2` 预发布——都会被拒绝；不提供旧接口回退，也不为退役宿主保留正向支持队列。Node.js 下限随 rc.1 宿主自身要求提高为 `>=24.9.0`，Cordis peer 随 rc.1 发布族更新为 `~4.1.0`。

### 变更

- 分析器输入身份重定为 `0.2.2-rc.1`（`v4-dsh022rc1.1`）。0.7.0 及更早版本创建的 semantic run 不再恢复：用创建它的版本完成，或新建 run；旧 run 与证据保留。确定性 CLI 缓存升至版本 10，旧条目自动忽略。
- 结构化调用者取消成为独立的已结算结局。rc.1 工具管线以结构化错误码 `ABORTED` / `ABORTED_BEFORE_DISPATCH` 分类调用者取消（rc.1 中 `run_code` 的调用者取消不再落入 `CODE_RUN_FAILED`）。两侧分析器将其计入新的 `tool_execution.outer_cancelled` / `inner_cancelled` 字段：绝不是成功、绝不是执行失败、绝不是审批拒绝，也不会宣称调用"没有执行"——执行体在结局结算前运行到静止，副作用仍可能已发生，保留的证据如实标注。对照向量把取消、真实失败、审批拒绝与未知结局四类判定固定为相互可区分。
- rc.1 适配对照真实发布包核验：V4 词汇与 rc.5 完全一致（62 个已知事件类型，零新增、零移除）；官方准入、会话契约、修复 fixture 与真实 Session/query/codec 服务检查全部在精确 rc.1 上运行。fork/继承、job/team/workflow/context 语义与隐私/资源边界原样保留。
- 测试与验收基础设施收敛到唯一当前 runtime：`tests/dsh-runtime` 与 `tests/dsh-host` 精确固定 `0.2.2-rc.1`；退役的 `tests/dsh-*-rc5` 树及其全部消费者（CI 矩阵、Windows workflow 默认值、审计 cohort、`.gitattributes`、README 命令）一并移除。CI 在三端跑 Node 24.9.0 下限，外加一个同一宿主上的 Node 25 探针单元。
- 商城材料中滞留的 0.5.2 时代 DSH/Node 声明刷新为 0.8.0 身份与同一组下限。

### 已知上游依赖缺口

rc.1 的 DSH 包（`dsh-commands`、`dsh-llm`、`dsh-agent`）仍精确依赖 `zod@4.4.3`（[GHSA-mrhx-c7xc-m3w5 / CVE-2023-54404](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)，修补版 4.6.6）。本项目的 peer 闭包、契约 runtime 树与宿主树精确 pin 的嵌套副本都解析到有漏洞的 4.4.3；完整宿主树顶层 `zod` 解析到已修补的 4.6.7。全新的 rc.1 生产扫描报告 18 个受影响包条目。我们既未证明某个具体 DSH 入口可利用，也未测得日用触发概率。

0.7.0 的例外已随其集合失效，且未续期。2026-11-06 维护者针对 0.8.0 及已审查的 rc.1 集合作出新的限定风险接受决定：绑定的清单/锁/runtime/宿主树身份、host queue，以及两个已审查的 18 条目图谱变体。该决定不表示漏洞已修复、不可达或扫描干净，也不覆盖新公告、版本或依赖变化及未审查的图；它按事件失效，没有日历到期时间或自动监测。本地源码检查中，全新的生产与全量 npm 扫描均在单一公告下报告 18 个受影响条目、退出码 1，并被归为 `accepted_known_risk`；这些是本地结果，不是精确提交的 CI 结果。详见[风险与决定状态](https://github.com/GreenLv/dsh-session-insights/blob/main/SECURITY.md#known-upstream-dependency-gap)。

### 升级与验证限制

安装本候选前，必须先把低于 `0.2.2-rc.1` 的宿主升级到至少 `0.2.2-rc.1`。历史 V4 会话日志仍是有效数据输入；旧确定性缓存自动忽略，删除属于另一次明确清理。单独安装的 Python CLI/Skill 通过其管理安装器更新。

开发阶段验证覆盖本仓库在精确 rc.1 runtime 上的适用源码与接口套件。双平台原生验收（安装制品、真实模型、GUI 与消费者接入检查）、精确提交 CI、canonical 制品冻结与发布属于后续独立门槛，由发布协调方执行；本文档**不**声明这些结果。

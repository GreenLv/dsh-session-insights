# DSH Session Insights 0.7.0

> Candidate notes. This file is the release-body draft; the version is not published. The limited security decision is recorded below; replacement artifact and affected identity checks and exact-commit CI are pending.

## English

DSH Session Insights 0.7.0 publishes Russian as a first locale and moves native acceptance to DSH `0.2.1-rc.5`. The declared floor stays `>=0.2.1-rc.2`, and `0.2.1-rc.2` keeps compatibility coverage; runs created by 0.6.1 stay resumable because the input identity and semantic schema are unchanged.

### Changes

- Russian (`--locale ru`) ships across the deterministic report, HTML dashboard, semantic prompts, native runtime and Python CLI, with a full Russian README. Message texts moved into keyed catalogs, so untrusted-data notices and prompt rules are written natively per locale instead of one English constant for every language.
- The primary acceptance host is now DSH `0.2.1-rc.5`. Upstream rc.4/rc.5 changes (an ACP stdout fix and thinking-display improvements) touch the host application layer; the Session/V4 catalog, `sessionQuery`, commands/tools, optional approval and cancel/dispose surfaces this plugin consumes are byte-identical between rc.3 and rc.5 in the published packages, so no product change was required for them. This plugin does not use the reasoning-body UI slot affected by the `text`/`rawText` migration.
- Acceptance tooling reports failures truthfully: real exit codes for failed steps and cleanup failures, isolated result directories that are never overwritten or silently reused, scene preservation when a cleanup stop state is unclear, and diagnostics without arbitrary exception text or machine paths. Fault probes are CRLF-portable.
- Dependency auditing scans a private copy of the bound package manifest and lock, and refuses failed or drifted inputs. This keeps a result tied to the files scanned; the audit mechanism itself does not accept the known upstream risk.
- CI cells install and name the exact DSH runtime they test (rc.5 primary, rc.2 compatibility), duplicate suites were reduced, and candidate artifacts are packed from the actual PR head instead of the merge checkout.

### Known upstream dependency gap

Six official DSH packages through rc.5 still pin `zod@4.4.3` exactly ([GHSA-mrhx-c7xc-m3w5 / CVE-2023-54404](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5), patched in 4.6.6). The full rc.5 host tree resolves its top-level `zod` to the patched 4.6.7, but the exact-pinned nested copies remain 4.4.3, and this project's peer closure resolves to 4.4.3. We have not established a reachable DSH exploit path or measured everyday trigger probability.

The 0.6.1 exception expired with its release cohort and was not renewed. On 2026-11-03 the maintainer made a new limited decision accepting this known risk for 0.7.0 and the exact reviewed rc.2/rc.5 dependency and host-queue cohort and two vulnerability graph variants. The 2026-11-02 scans reported the single advisory with 23–24 affected package entries depending on the resolving npm version (one resolution adds `@deepseek-ai/dsh-typert-protocol`, which declares the still-vulnerable `zod@^4.4.3` range). Acceptance does not mean the issue is fixed, unreachable or clean; it does not extend to new advisories or changed versions, dependencies or unreviewed graphs. The decision is event-bound with no calendar expiry or automatic monitoring. In local source checks, fresh production and full npm scans each reported the single advisory with 23 affected entries and exited 1; the policy-aware assessment classified both as `accepted_known_risk`. The separately reviewed 24-entry report fixture was also accepted. These are not exact-commit CI results. See the [risk and decision status](https://github.com/GreenLv/dsh-session-insights/blob/main/SECURITY.md#known-upstream-dependency-gap) and the [upstream report](https://github.com/deepseek-ai/deepseek-harness/discussions/10847).

### Upgrade and validation limits

Runs created by 0.6.1 remain resumable and existing HTML/JSON/Markdown reports stay readable; old deterministic caches are ignored automatically and removing them is a separate deliberate cleanup. Update separately installed Python CLI/Skill consumers through their managed installer.

As of 2026-11-03, the recorded checks include installed-artifact and native backend tests, budgeted real-model runs, and the required isolated on-screen Desktop command dispatch on macOS and Windows. The Windows GUI scene produced a Russian report with no new model or stream events in its GUI session; this is not a Windows browser visual check. The Windows Python suite passed in an approved UAC environment; earlier standard-user failures and the cross-user ACL limit remain. One Windows Russian model output contained four Han characters. The three-language HTTP report-UI and macOS real-model results retain their earlier artifact identities under the byte-identical runtime reuse decision. Details and other inherited limits, including the full-profile missing-approval branch, layout advisories and whole-host resource measurement, are in the [candidate acceptance record](../acceptance/v0.7.0-candidate.md). The packaged risk notice has changed, so a replacement artifact and affected installation identity checks and exact-commit CI remain pending; this candidate is not publishable until those gates are resolved.

## 简体中文

DSH 会话洞察 0.7.0 将俄语作为正式 locale 发布，并把原生验收迁移到 DSH `0.2.1-rc.5`。声明下限仍为 `>=0.2.1-rc.2`，`0.2.1-rc.2` 保留兼容覆盖；由于输入身份与语义 schema 未变，0.6.1 创建的 run 仍可 resume。

### 变更

- 俄语（`--locale ru`）覆盖确定性报告、HTML 仪表板、语义提示、原生 runtime 与 Python CLI，并提供完整俄语 README。消息文本迁移到键控目录：不可信数据警示与提示规则按 locale 原生书写，不再对所有语言使用同一条英文常量。
- 主要验收宿主更新为 DSH `0.2.1-rc.5`。上游 rc.4/rc.5 的变化（ACP stdout 修复、思考展示优化）位于宿主应用层；本插件消费的 Session/V4 catalog、`sessionQuery`、commands/tools、可选审批与取消/卸载面在 rc.3 与 rc.5 的已发布包中逐字节一致，因此无需产品改动。本插件未使用 `text`/`rawText` 迁移涉及的 reasoning-body UI Slot。
- 验收工具如实报告失败：失败步骤与清理失败返回真实退出码，隔离结果目录不被覆盖或隐式复用，清理停止状态不明时保留现场，诊断不携带任意异常文本或本机路径。故障探针在 CRLF 环境下可移植。
- 依赖审计扫描已绑定的包清单和锁文件的私有副本，并拒绝失败或发生漂移的输入，使结果对应实际扫描的文件；审计机制本身不构成对已知上游风险的接受。
- CI 各单元安装并指名其测试的确切 DSH runtime（rc.5 主宿主、rc.2 兼容），减少重复套件；候选制品从真实 PR head 打包而非 merge checkout。

### 已知上游依赖缺口

直到 rc.5，六个 DSH 官方包仍精确依赖 `zod@4.4.3`（[GHSA-mrhx-c7xc-m3w5 / CVE-2023-54404](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)，修补版 4.6.6）。完整 rc.5 宿主树根级 `zod` 已解析到已修补的 4.6.7，但精确 pin 的嵌套副本仍为 4.4.3，本项目的 peer 闭包也解析到 4.4.3。我们既未证明某个具体 DSH 入口可利用，也未测得日用触发概率。

0.6.1 的例外已随其发布集合失效，且未续期。2026-11-03 维护者针对 0.7.0 及已审查的 rc.2/rc.5 依赖、宿主队列集合和两种漏洞图作出新的限定风险接受决定。2026-11-02 的扫描在同一公告下报告 23–24 个受影响包条目（随解析所用 npm 版本而异：其一计入声明仍受漏洞影响 `zod@^4.4.3` 范围的 `@deepseek-ai/dsh-typert-protocol`）。该决定不表示漏洞已修复、不可达或扫描干净，也不覆盖新公告、版本或依赖变化及未审查的图；它按事件失效，没有日历到期时间或自动监测。本地源码检查中，新执行的生产与全量 npm 扫描各报告该公告下 23 个受影响条目并退出 1；策略评估将两者分类为 `accepted_known_risk`，另一个已审查的 24 条目报告夹具也被接受。这些本地结果不代表精确提交的 CI 已通过。详见[风险与决定状态](https://github.com/GreenLv/dsh-session-insights/blob/main/SECURITY.md#known-upstream-dependency-gap)及[上游报告](https://github.com/deepseek-ai/deepseek-harness/discussions/10847)。

### 升级与验证限制

0.6.1 创建的 run 仍可 resume，既有 HTML/JSON/Markdown 报告继续可读；旧确定性缓存被自动忽略，删除属于另一次明确清理。单独安装的 Python CLI/Skill 通过其管理安装器更新。

截至 2026-11-03，已记录安装制品与原生后台检查、有预算的真实模型运行，以及 macOS 和 Windows 隔离 Desktop 上必需的屏上命令分派。Windows GUI 场景生成了俄语报告，GUI 会话没有新增模型或流事件；这不代表已在 Windows 浏览器中完成视觉检查。Windows Python 全套在获准的 UAC 环境中通过，普通用户先前的失败和跨用户 ACL 限制仍保留。一处 Windows 俄语模型输出含四个汉字。三语 HTTP 报告 UI 和 macOS 真实模型结果按运行时代码字节相同的依据复用，仍保留原制品身份。详细结果及其余继承限制（完整 profile 缺审批服务分支、布局建议和全宿主资源测量）见[候选验收记录](../acceptance/v0.7.0-candidate.md)。打包内风险说明已更新，替代制品冻结及受影响的安装身份检查、精确提交的 CI 仍待完成；这些门槛解决之前，本候选不可发布。

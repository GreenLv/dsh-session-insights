# DSH Session Insights 0.8.1（候选，未发布）

> 状态：开发候选。本文只声明已有证据；发布日期、发布提交、tgz SHA-256、CI 与双平台原生验收由发版阶段填写。任何标注“待”的小节在发布前必须替换为真实回执。

## English

0.8.1 is a patch release that raises the supported host floor: it requires DeepSeek Harness (DSH) `>=0.2.2-rc.2` (0.8.0 required `>=0.2.2-rc.1`) and Node.js `>=24.9.0`, with Cordis `~4.1.0`. rc.1 and older hosts are refused; later releases stay admitted by the declared range. The results in this document come from the source and contract checks for the development candidate `f569660…` against DSH `0.2.2-rc.2`, the exact host the candidate trees resolve.

### What changed

- The analysis identity is retargeted to `v4-dsh022rc2.1` (target `0.2.2-rc.2`). Semantic runs recorded by 0.8.0 or earlier do not resume under this identity; finish them with the version that created them or start a new run. Deterministic CLI caches are invalidated and rebuilt; existing runs, evidence and saved HTML/JSON/Markdown reports are retained.
- The product vocabulary is the official rc.2 catalog exactly (63 event types, including `team/mode`). Unknown required events keep the explicit rejection.
- rc.2 structured approval non-grants are classified from their persisted codes: `APPROVAL_REJECTED` counts as a permission boundary, while `APPROVAL_CANCELLED` and `APPROVAL_UNAVAILABLE` are separate blocked outcomes (`tool_execution.approval_cancelled`, `approval_unavailable`) — never caller cancellations, human rejections or execution failures, and never inferred from success text.
- `team/mode` records count as team configuration context (`team.mode_changes`), never as user work, authorization or completion.
- The rc.2 release family fixes the upstream `zod@4.4.3` pin (now `4.6.6`), so the supported peer closure and the root production/full scans no longer report GHSA-mrhx-c7xc-m3w5. The 0.8.0 exact-cohort exception is retired; no new exception is granted.

### Verification recorded so far

- Official strict-catalog, Session/append-overload, service, repair-fixture and native/PTC executor contracts pass on the exact rc.2 runtime/host trees; the JS suite passes 238 checks and the Python suite 208 (including the rc.2 semantics regressions). Exact PR-head CI and packaged-artifact checks: 待（发版阶段由精确源码 CI 产生）.
- Dependency audits run per tree with retained raw results: root production/full clean, rc.2 runtime clean, Python clean. The rc.2 host tree scan reports 10 upstream advisories (75 affected entries) inside the host's own dependency closure — `undici` 8.0.0–8.12.1 (four high), the MCP TypeScript SDK 2.0.0–2.2.2, and `fflate` 0.8.0–0.8.2. These come from the upstream host release; see [SECURITY](../../SECURITY.md#known-upstream-dependency-gap). Release stays gated on a maintainer decision for this exact closure.

## 简体中文

0.8.1 是提高宿主下限的补丁版本：要求 DeepSeek Harness（DSH）`>=0.2.2-rc.2`（0.8.0 要求 `>=0.2.2-rc.1`）和 Node.js `>=24.9.0`，Cordis `~4.1.0`。rc.1 及更早宿主会被拒绝；更高版本按声明范围准入。本文结果来自开发候选 `f569660…` 针对精确宿主 DSH `0.2.2-rc.2`（候选测试树实际解析的版本）的源码与契约检查。

### 主要变化

- 分析身份改为 `v4-dsh022rc2.1`（目标 `0.2.2-rc.2`）。0.8.0 及更早版本创建的语义分析在本身份下不能恢复：请用创建它的版本完成，或新建分析。确定性 CLI 缓存自动失效重建；既有运行、证据和已保存的 HTML、JSON、Markdown 报告均保留。
- 产品事件集合就是官方 rc.2 目录（63 个事件类型，含 `team/mode`）。未知必需事件保持明确拒绝。
- rc.2 的结构化审批未放行结果按持久化错误码分类：`APPROVAL_REJECTED` 计入权限边界；`APPROVAL_CANCELLED` 和 `APPROVAL_UNAVAILABLE` 是独立的“未放行”结果（`tool_execution.approval_cancelled`、`approval_unavailable`）——不是调用者取消、不是人工拒绝、不是执行失败，也不会从成功文本推断。
- `team/mode` 计为团队配置上下文（`team.mode_changes`），不算用户任务、授权或完成。
- rc.2 系列修复了上游 `zod@4.4.3` pin（现为 `4.6.6`）：受支持的对等闭包和 root 生产/完整扫描不再命中 GHSA-mrhx-c7xc-m3w5。0.8.0 的精确 cohort 例外退役，本轮不授予新例外。

# DSH Session Insights 0.6.1

## English

DSH Session Insights 0.6.1 strengthens the boundary between source logs and report files, keeps same-named projects separate, and refuses semantic summaries built from outdated evidence. DSH 0.2.1-rc.3 is the primary tested host; 0.2.1-rc.2 remains the supported floor.

### Changes

- Cleanup tools require the host's human approval for the exact deletion call. The plugin now finds an optional approval service supplied by another host plugin; preview stays read-only, and typed cleanup commands remain available.
- Report writes refuse unsafe source-tree targets, links, hard links and conflicting paths before writing. Caches store only bounded, privacy-projected data; submitted model text must pass validation.
- Reports use one captured timezone and stable anonymous project identities. Aggregates must match the current validated batch content; rebuild stale aggregates or choose an explicit deterministic fallback.
- Python CLI output supports redirected UTF-8 Chinese and space-containing paths on Windows. CI covers both supported DSH cohorts and scans production, full Node and declared Python dependencies.

### Known upstream dependency gap

DSH rc.2/rc.3 pins `zod@4.4.3`, affected by [GHSA-mrhx-c7xc-m3w5 / CVE-2023-54404](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5). A large array with many invalid elements can exhaust memory in an affected validation path; the patched Zod version is 4.6.6. This release does not fix that upstream dependency. We have not established a reachable DSH exploit path or measured everyday trigger probability.

The maintainer accepts only this advisory/package version for 0.6.1 and the current rc.2/rc.3 dependency cohort. CI keeps the raw finding and still blocks other high/critical findings and unsuccessful scans. The exception expires when the release version or reviewed DSH dependency cohort changes. At the next DSH upgrade, rerun the scans and remove it after the dependency is fixed; a later rc is not itself proof of a fix. If the gap remains, reassess it explicitly. See the [full scope](https://github.com/GreenLv/dsh-session-insights/blob/v0.6.1/SECURITY.md#known-upstream-dependency-gap-in-061) and [upstream report](https://github.com/deepseek-ai/deepseek-harness/discussions/10847).

### Upgrade and validation limits

Start a new analysis run after upgrading. Existing HTML/JSON reports remain readable. Old cache formats are ignored; removing them is a separate deliberate cleanup. Update separately installed Python CLI/Skill consumers through their managed installer.

Acceptance covers source/contract checks, installed artifact manifests and macOS/Windows command, approval and backend flows. Unchanged semantic/model/UI components retain their original evidence identities. Desktop backend checks do not establish main-application GUI behavior; Windows private ACL rules were observed, but cross-user denial was not exercised. The full-profile missing-approval-service branch was not run; a separate real-SDK negative control verifies fail-closed behavior. A horizontal-overflow layout advisory remains around a 538px viewport. These limits are retained rather than described as complete coverage.

## 简体中文

DSH 会话洞察 0.6.1 加强源日志与报告文件的写入边界，区分同名项目，并拒绝使用过期证据生成的语义汇总。DSH 0.2.1-rc.3 是主要实测宿主，0.2.1-rc.2 继续作为支持下限。

### 变更

- 工具删除运行目录时，需要宿主对具体调用作出人工批准。修复了无法找到其他宿主插件提供的可选审批服务的问题；预览仍只读，人工输入的清理命令继续可用。
- 报告在写入前拒绝源日志目录、链接、硬链接与冲突路径。缓存仅保留有界、按隐私模式投影的数据；模型提交内容经过校验才会被接受。
- 同一报告使用入口捕获的时区和稳定匿名项目身份。aggregate 必须对应当前已验证批次，过期时重新构建，或明确选择确定性降级。
- Python CLI 在 Windows 重定向输出中支持 UTF-8 中文和含空格路径。CI 覆盖两个受支持的 DSH 宿主集合，并扫描生产、全量 Node 和声明的 Python 依赖。

### 已知上游依赖缺口

DSH rc.2/rc.3 固定依赖的 `zod@4.4.3` 受 [GHSA-mrhx-c7xc-m3w5 / CVE-2023-54404](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5) 影响。超大数组中的大量无效项进入受影响校验路径时，可耗尽内存；Zod 修补版为 4.6.6。本次发版没有修复该上游依赖，也没有证明某个具体 DSH 入口可利用或测得日用触发概率。

维护者仅为 0.6.1、该公告/依赖版本及当前 rc.2/rc.3 依赖集合接受风险。CI 保留原始命中，其他 high/critical 及扫描失败仍阻断。发布版本或已审查的 DSH 依赖集合变化会使例外失效。下次升级 DSH 时须重新扫描，确认依赖修复后移除例外；仅看到新 rc 不能视为已修复。若缺口仍在，必须重新明确评估。详见[完整范围](https://github.com/GreenLv/dsh-session-insights/blob/v0.6.1/SECURITY.md#known-upstream-dependency-gap-in-061)及[上游报告](https://github.com/deepseek-ai/deepseek-harness/discussions/10847)。

### 升级与验证限制

升级后请新建分析运行。已有 HTML/JSON 报告仍可阅读；旧缓存格式会被忽略，删除旧缓存是另一次明确清理操作。单独安装的 Python CLI/Skill 需通过其管理安装器分别更新。

验收覆盖源码/合同检查、已安装制品清单及 macOS/Windows 命令、审批与后台链路。未变的语义、模型和页面组件保留原证据身份。Desktop 后台检查不证明主程序 GUI 行为；Windows 私有 ACL 规则已观察，但未执行跨用户拒绝测试。完整 profile 的审批服务缺失分支未运行，另有真实 SDK 负例验证失败关闭。约 538px 视口仍有横向溢出的布局建议。这些限制均予保留，不表述为全覆盖。

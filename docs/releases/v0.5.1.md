## 中文

本版适配 DeepSeek Harness `0.2.0-rc.1`，并把官方恢复结果从确认失败中分离出来。

### 变化

- 官方宿主在收尾被中断的步骤时会写入 `TOOL_OUTCOME_UNKNOWN`（已记录调用、结果未持久化，可能有副作用）与 `TOOL_NOT_STARTED`（日志无调用开始记录）两种恢复结果。报告在会话与总量中用 `tool_recovery: {outcome_unknown, not_started}` 单独计量：不计工具失败、不计验证失败、不产生权限证据，也不会建议对可能有副作用的操作直接重试。恢复结果按官方 `(callId, turn, step)` 身份结算；同一 ID 在后续轮次是新的待决请求。仅正文提到恢复码的文本仍按一般结果规则分类。
- 只支持 DSH `0.2.0-rc.1`：全部 DSH peer、`engines.dsh` 与 Bundle 元数据精确固定；输入身份升级为 `v4-dsh020rc1.1`，旧 manifest 与确定性缓存随之失效。旧原始日志仍需先经上游 DSH 迁移。
- 恢复 fixture 语料改由精确目标包的官方 `ToolCallRecovery` 生成，覆盖未开始、未知结果、混合分组、跨轮次同 ID、surface 替换、已结算、纯文本与无 code 控制，并对官方恢复语料做 3 种隐私 × 2 种语言的 Node/Python 对等检查。

### 升级

DSH `0.2.0-rc.1` 是唯一支持的宿主版本，Node.js 要求 `^22.19.0 || >=24.0.0`。Bundle 无需 Python；单独安装的 Python CLI/Skill 需另行更新至 0.5.1。升级后请新建分析运行；已有报告保留。

## English

This version adapts session retrospectives to DeepSeek Harness `0.2.0-rc.1` and separates official recovery results from confirmed failures.

### Changes

- When DSH closes an interrupted step it can write official recovery results: `TOOL_OUTCOME_UNKNOWN` (a recorded call whose completed outcome was not durably recorded; side effects possible) and `TOOL_NOT_STARTED` (no record of the call starting). The report counts them separately as `tool_recovery: {outcome_unknown, not_started}` per session and in totals: neither is a tool failure, a failed verification or permission evidence, and the report never recommends directly retrying an operation that may have had side effects. Recovery settles by the official `(callId, turn, step)` identity, so the same id in a later turn is a distinct pending request. Text that merely mentions a recovery code keeps ordinary result rules.
- DSH `0.2.0-rc.1` is the only supported host: all DSH peers, `engines.dsh` and Bundle metadata pin it exactly; input identity moves to `v4-dsh020rc1.1`, invalidating old manifests and deterministic caches. Older raw logs still require upstream migration first.
- The recovery fixture corpus is now generated through the official `ToolCallRecovery` of the exact target package, covering not-started, outcome-unknown, mixed groups, same id across turns, surface replacement, settled calls, text-only mentions and no-code errors, with Node/Python parity over the official recovery corpus across 3 privacy modes × 2 locales.

### Upgrade

DSH `0.2.0-rc.1` is the only supported host version and Node.js must satisfy `^22.19.0 || >=24.0.0`. The Bundle needs no Python; update a separately installed Python CLI/Skill to 0.5.1 independently. Start a new analysis run after upgrading; existing reports are retained.

Completed source-level checks: npm ci (root and target runtime closures resolve to exactly 0.2.0-rc.1), 73 Python tests, 79 Node tests, the contract/repair/services gates, the public-tree audit and the full deterministic matrix passed locally. The canonical artifact, actual macOS/Windows hosts, real-model semantic workflow, human bilingual browser checks and publication readback have not run yet; see the gate table in the [candidate acceptance record](https://github.com/GreenLv/dsh-session-insights/blob/main/docs/acceptance/v0.5.1-candidate.md).

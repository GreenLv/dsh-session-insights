# DSH Session Insights 0.5.1

## 中文

本版适配 DeepSeek Harness `0.2.0-rc.1`。工具调用被中断后，宿主补写的恢复结果会单独计数，避免把没有最终结果的调用误算为已确认失败。

### 变化

- JSON 总量和会话摘要新增 `tool_recovery: {outcome_unknown, not_started}`。两种恢复状态都不计入工具失败、验证失败、权限或重试计数；同一调用 ID 在不同轮次的证据分别保留。
- `TOOL_OUTCOME_UNKNOWN` 表示日志记录了调用，但未记录最终结果；`TOOL_NOT_STARTED` 表示日志没有该调用开始的记录。它们都不能证明工具执行过或没有执行。重试可能改变数据的操作前，应先核实外部状态。

### 升级

只支持 DSH `0.2.0-rc.1`，Node.js 要求 `^22.19.0 || >=24.0.0`。Bundle 无需 Python；单独安装的 Python CLI/Skill 需另行更新到 0.5.1。升级后请新建分析运行，旧 manifest 和缓存不能继续使用；已有 HTML、JSON 和 Markdown 报告保留。旧原始日志需先由上游 DSH 迁移为 V4。

```sh
dsh plugin --profile web add dsh-session-insights@0.5.1
```

源码检查、安装包和实际宿主的验证范围分别记录，详见随 Release 提供的 `release-acceptance.md`。[冻结候选记录](https://github.com/GreenLv/dsh-session-insights/blob/v0.5.1/docs/acceptance/v0.5.1-candidate.md)保留发布前的状态。

## English

This patch targets DeepSeek Harness `0.2.0-rc.1`. Recovery results written after an interrupted tool call are counted separately, so a missing final result does not become a confirmed failure.

### Changes

- JSON totals and session summaries add `tool_recovery: {outcome_unknown, not_started}`. Neither recovery status increases tool-failure, failed-verification, permission or retry counts. Reused call IDs retain separate evidence across turns.
- `TOOL_OUTCOME_UNKNOWN` means the log recorded the call but has no final result. `TOOL_NOT_STARTED` means it has no record of that call starting. Neither proves whether the tool executed. Check external state before retrying an operation that can change data.

### Upgrade

Only DSH `0.2.0-rc.1` is supported. Node.js must satisfy `^22.19.0 || >=24.0.0`. The Bundle needs no Python; update a separately installed Python CLI/Skill to 0.5.1 independently. Start a new analysis run after upgrading: earlier manifests and caches cannot resume. Existing HTML, JSON and Markdown reports are retained. Migrate older raw logs to V4 through upstream DSH first.

```sh
dsh plugin --profile web add dsh-session-insights@0.5.1
```

Source checks, package checks and actual-host results are recorded separately in the attached `release-acceptance.md`. The [frozen candidate record](https://github.com/GreenLv/dsh-session-insights/blob/v0.5.1/docs/acceptance/v0.5.1-candidate.md) preserves the pre-publication state.

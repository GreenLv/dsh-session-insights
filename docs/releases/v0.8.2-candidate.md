# DSH Session Insights 0.8.2 (candidate — acceptance pending)

## English

This candidate retargets the analysis contract to DSH `0.2.2-rc.3`. The full upstream rc.2→rc.3 diff was verified before implementation: only version bumps plus an upstream exporter robustness fix in `session-log-export`; none of the Session, catalog, query, agent, tools, LLM or app-boot sources this plugin consumes changed.

Version 0.8.2 requires DeepSeek Harness (DSH) `>=0.2.2-rc.3`. Upgrade an older host before installing; rc.2 and older hosts are refused. The declared range admits later host releases, which does not claim they have been tested. Node.js `>=24.9.0`, Cordis `~4.1.0` and Python `>=3.11` are unchanged.

### Changes and upgrade

- The analyzer identity moves to `v4-dsh022rc3.1`. Semantic runs recorded by 0.8.1 do not resume under 0.8.2: finish them with the version that created them or start a new run. Old deterministic caches are invalidated and rebuilt from source; existing reports can still be opened.
- The official rc.3 chat-export importer is covered by regression tests through the official persistence path: normal, web-search/fetch, attachment-card, excluded-reply and content-filtered conversations, and import-then-continue. The imported `deepseek-chat-export` source stays an observation label, never a local model request; missing usage stays unavailable instead of being fabricated as a measured zero.
- The web/headless acceptance driver now witnesses the target and non-target source logs across the real operation interval: loss, replacement, addition or read failure is never recorded as unchanged, and operation, witness and cleanup outcomes stay separate terminal states.
- The canonical artifact receipt records the real producer tool identity (Node, npm, packer, platform) and the manifest/lockfile input digests at pack time. Consumers keep verifying commit, digest and installed bytes.

### Verification status (candidate boundary)

- JS suite 259/259 and Python suite 213/213 pass on the exact rc.3 runtime; the official `dsh-app-boot` consumer admits rc.3 and refuses rc.2, rc.1, older lines and malformed versions.
- Isolated macOS Web and Headless profile acceptance against an installed artifact passed all 21 gates, including the new source-log witness and cleanup confirmation. Official Desktop GUI, Windows same-artifact acceptance, real-model scenes and publication are **not claimed** by this candidate.
- Dependency scans: root production/full and the slim rc.3 runtime tree are clean; Python is clean. The full rc.3 host still reports the same ten advisories reviewed for 0.8.1 (75 affected package entries, 1 high). The 0.8.1 decision does not carry forward; the host finding is pending a new maintainer decision and blocks the release gate. See the [security policy](../SECURITY.md#known-upstream-dependency-gap).

This file records the candidate boundary. Release identity, CI status and native acceptance are appended by the release process only after they exist.

## 简体中文

本候选把分析契约调整到 DSH `0.2.2-rc.3`。实施前已核对 rc.2→rc.3 完整上游差异：只有版本号提升，以及 `session-log-export` 的一处上游导出器健壮性修复；本插件消费的 Session、目录、查询、agent、tools、LLM 与 app-boot 源码均未变化。

0.8.2 要求 DeepSeek Harness（DSH）`>=0.2.2-rc.3`。旧宿主请先升级，rc.2 及更早宿主会被拒绝。声明范围允许后续宿主版本准入，这不等于已经实测。Node.js `>=24.9.0`、Cordis `~4.1.0`、Python `>=3.11` 不变。

### 变化与升级

- 分析身份更新为 `v4-dsh022rc3.1`。0.8.1 记录的语义分析在 0.8.2 下不能恢复：请用创建它的版本完成或重新开始。旧确定性缓存自动失效并重建；既有报告仍可打开。
- 官方 rc.3 聊天导出导入器已通过官方持久化路径纳入回归覆盖：正常问答、网页搜索/抓取、附件卡片、被排除回复与内容过滤会话、导入后继续对话。导入源 `deepseek-chat-export` 只是观察标签，不计为本地模型请求；缺失的用量保持未知，不会编造为实测零值。
- Web/Headless 验收驱动现在对实际操作区间前后的目标与非目标源日志做摘要见证：丢失、替换、增加或读取失败都不会被记为 unchanged；操作结果、见证结果与清理结果分别保留终态。
- 候选制品回执在打包时记录真实生产者工具身份（Node、npm、打包器、平台）与清单/lock 输入摘要。消费者继续校验 commit、摘要与安装字节。

### 验证状态（候选边界）

- JS 259/259、Python 213/213 在精确 rc.3 运行时通过；官方 `dsh-app-boot` 消费者准入 rc.3，拒绝 rc.2、rc.1、更早版本和坏版本。
- macOS 隔离 Web 与 Headless profile 对已安装制品的验收全部 21 项 gate 通过，含新增源日志见证与清理确认。官方 Desktop GUI、Windows 同制品验收、真实模型场景与发布**不在本候选声称范围**。
- 依赖扫描：根生产/完整依赖与精简 rc.3 运行时 clean；Python clean。rc.3 完整宿主仍报告与 0.8.1 相同的十项公告（75 个受影响包条目，1 项 high）。0.8.1 的决定不顺延；宿主发现待维护者新决定，阻塞发布门槛。详见[安全说明](../SECURITY.md#known-upstream-dependency-gap)。

本文件只记录候选边界。发布身份、CI 状态与原生验收仅在其存在后由发布流程补充。

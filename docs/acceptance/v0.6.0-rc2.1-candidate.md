# DSH Session Insights 0.6.0 (DSH 0.2.1-rc.2) candidate review

0.6.0 adapts Session Insights to DSH `0.2.1-rc.2` and moves the floor to `>=0.2.1-rc.2`; DSH `0.2.0-rc.2` and `0.2.1-rc.1` are refused. The host keeps session format 4 but adds required event vocabulary and new completion/delegation semantics, so a new analysis run is required after upgrading. Existing reports remain on disk. A separately installed Python CLI or Skill requires its own update.

This is a candidate record produced by the implementing session. It is not a publication, does not claim dual-platform native acceptance, and does not establish real-model or Desktop UI behavior. The follow-up native acceptance session owns the remaining gates.

## Implemented scope

- **SI021-01:** `job/registered`, `job/settled` and `working-directory/change` are admitted by the Node and Python validators and by the production parse entrypoints. Unknown required events are still refused; unknown ignorable events, including `plugin:` records, are safely skipped. Fixtures are written by the exact 0.2.1-rc.2 `Session` writer and restored by the official strict catalog; the recorded pre-fix failure was `unknown required V4 event`.
- **SI021-02:** background jobs are counted by registry lifecycle (registered/settled/completed/failed/killed/pending, inherited and inherited-pending, by-kind/by-cause, teardown, unreported producer outcome, unpaired settlements, turn-ends while an owned job was still running). Registry settlement is never reported as user-task completion or resource release. Delegation evidence is counted separately: `subagent`/`subagent_fork`/`workflow`/`spawn_teammate` dispatch results, runtime `subagent-settled` notices, `tool-jobs` completion notices, inbound/outbound relays, workflow run/agent records, and Team roster/task snapshots. Delivery, inbox acceptance and parent turn end are not completion.
- **SI021-03:** working-directory changes form a labelled trajectory; the immutable header cwd remains the origin project used for filtering and resume. Own vs inherited segments, cross-project activity, platform path forms, and duplicate/relative/invalid change anomalies are reported; raw paths stay out of redacted/metrics reports.
- **SI021-04:** typed `plugin:` records are retained as opaque type/count coverage only; mixed physical V4 range encoding, fork/seed inherited prefixes (including inherited open jobs), interrupted-tail recovery fixtures and unknown-required refusal are covered.
- **SI021-05:** `web_search` and `web_fetch` are recognised as recorded calls (one multi-query search is one call); legacy `web.*` search aliases and PTC outer/inner separation are preserved. `model/selection`, reasoning effort, scheduled vs performed `llm/retry` attempts with chain ids, and per-session token provenance (`input_tokens`/`total_tokens` derived sums, raw buckets recorded) are reported.
- **SI021-06:** npm/Python/Bundle/Skill identity is 0.6.0; engines, nested Bundle compatibility and DSH peers are `>=0.2.1-rc.2`; Cordis runtime identity is 4.0.5; the fixture runtime is pinned to exact 0.2.1-rc.2; real `dsh-app-boot` admission and version-vector tests pass.
- **SI021-07:** session-query lease/cancel/error handling, Worker concurrency/cancel/unload, and `--no-open` report-path behavior keep their existing isolation coverage, re-run against the 0.2.1-rc.2 fixture runtime.

Valid orphan settlements remain readable and counted. ## Compatibility, privacy and migration notes

- Input remains V4. Logs written by 0.2.0-rc.2 remain readable because their vocabulary is a subset; the host version itself is admitted by range, not by a static table. Logs containing events this reader does not know and that are not marked `ignorable` are refused rather than silently truncated.
- A job is a registry/producer record. `completed` does not prove user-task completion, delivered output, or resource release; `producerReported` does not certify cleanup. A registered job without a settlement is pending, including after its parent turn ends. A structurally valid settlement whose registration append was lost is counted as an integrity anomaly instead of making the whole session unreadable; malformed terminal fields are refused with or without a registration.
- Team phase/task snapshots and inbox relays are recorded state, not Lead task completion. `active` is a lifecycle phase, not progress.
- Working-directory labels are exposed; raw paths are not added to redacted/metrics reports. Filtering and resume continue to use the immutable header cwd, so an existing project filter does not silently change meaning after a `cd`.
- `plugin:` record payloads are never interpreted as intent, model context or completion evidence. Their type/count coverage is retained; migration may lose them without changing how the rest of the log is read.
- Token buckets are recorded per step; `total_tokens` is a derived consistent sum and is labelled accordingly. Reasoning is an output subset and is never added twice. No currency pricing is inferred.

The first sandboxed Web startup failed at `listen EPERM` on `127.0.0.1`. Repeating the same isolated profile startup in system context succeeded and printed a live local URL; the failure is classified as a command-sandbox socket restriction, not a Bundle load failure.

The first independent macOS DSH review found unsafe ordered substring replacement in the English Dashboard, incomplete resume/cancellation/repair-to-fallback coverage, and an unsupported follow-up `ContextForm`. The second review confirmed those repairs, then reproduced a false run-root rejection when a canonicalized `/private/var` root was compared with a not-yet-created `/var` child, and found three framework-owned Chinese strings in a semantic English report. The candidate now canonicalizes through the deepest existing ancestor and localizes those semantic-finalization strings. A third independent macOS review closed both findings: two semantic prepares and two deterministic commands succeeded under a `/var`-aliased DSH home, a complete English semantic report rendered with zero CJK characters outside scripts, all 10 Node and 35 Python tests passed, and the audited npm payload contained the intended 17 files. No remaining macOS release blocker was found.

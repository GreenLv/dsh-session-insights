`tests/rc2-runtime/package-lock.json` pins the isolated service/contract harness. It does not change a daily DSH installation. `build_rc2_fixture.mjs` regenerates the extended plaintext and compressed fixtures through the exact official codec/catalog. The verifier rejects absent runtimes, mixed DSH versions, absent fixtures and empty logs; it reports checked files, events and package code hashes. Never count an unavailable test as a pass.

## Remaining native steps

Use a fresh DSH_HOME and an exact rc.2 runtime, then install the same candidate tarball into a new profile. Do not reuse a daily profile or treat a source checkout as the package under test.

1. Start a session, complete a real model turn, then enable the Bundle. Verify seven tools and one command, automatic developer additions, disable/removal and re-enable without duplicate registration.
2. Run `/session-insights --deterministic --locale en`, then a nonempty semantic run. Confirm the notice is queued, executed, persisted and survives restart. Exercise one invalid batch repair followed by explicit fallback.
3. Cancel during listing, cold reading, Worker analysis and before semantic persistence; unload while work is pending and confirm no later artifact writes.
4. Repeat registration, deterministic analysis, cancellation, path and report checks on Windows. Record semantic/model coverage separately.
5. Bind every result to the candidate tarball SHA-256. If bytes change, repeat affected acceptance. Record real provider/model identity without recording credentials or private prompt content.

# DSH Session Insights 0.5.2 candidate review

0.5.2 continues the 0.5.x host-adaptation and repair series. It requires DSH `>=0.2.0-rc.2`, refuses RC.1, and requires a new analysis run after upgrading from 0.5.1. Existing reports remain on disk. A separately installed Python CLI or Skill requires its own update.

The unpublished development candidates used version 0.6.0. Their [independent repair and qualification record](v0.6.0-candidate.md) remains historical evidence; their packages and receipts are not relabelled as 0.5.2. The release version was revised before tag, npm or GitHub Release publication. No new command, tool or report module was added in this repair round.

The final version change updates package and Python metadata, the analyzer version displayed in reports, current install instructions and packaging assertions. V4 input identity remains `v4-dsh020rc2.1`; report and semantic schemas, model validation, selection logic and the dashboard implementation remain unchanged. Compatibility admission does not establish that a future host has been tested.

Source/CI checks and the commit-bound artifact are recorded separately. The final artifact must pass native installation, strict second-install no-op, reinstall, full loaded-file identity, tool/command mounting and populated report-version checks on macOS and Windows Web, Headless and official Desktop. Prior runtime, GUI, model and page results are reused only with exact input hashes and explicit scope; version and installation results are freshly checked.

Real-provider positive output is labelled as schema-guided. The actual Headless negative test deliberately submits invalid output, attempts one still-invalid repair and generates a marked fallback. It does not establish naturally occurring model failure. HTTP observations, static self-containment checks and the user's offline local-file observations remain separate evidence.

This page records the candidate process. Publication and public artifact readback remain separate gates. Complete receipts and any residual acceptance limits are retained by the coordinating review and attached to the release when publication is verified.

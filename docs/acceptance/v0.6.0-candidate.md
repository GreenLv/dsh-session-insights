# DSH Session Insights 0.6.0 candidate review

0.6.0 raises the minimum host to DSH `>=0.2.0-rc.2`, binds native resume to a recorded selection scope, and limits concurrent analysis and file-log decoding. This is a candidate record. Tag, npm and GitHub Release publication require the remaining native and model gates; a passing source suite does not establish Desktop support.

## Independent review

The initial development commit was independently checked. Its tarball is superseded by the repaired candidate: project-filtered semantic preparation threw an error, the analysis scheduler could run eight Workers together, and compressed Python reads expanded an entire frame before enforcing their budget. Resume fingerprints were written but not checked, and `--no-open` returned a labelled line instead of the documented path.

| Family | Repair and executable coverage |
| --- | --- |
| SI-RC2-001 version admission | Both locks pass strict `npm ci` in fresh directories without `--legacy-peer-deps`. `scripts/verify_dsh_admission.mjs` exercises the actual RC.2 app-boot consumer against the floor, later prereleases/stable releases, build metadata and malformed versions. Constructed future versions establish admission only. |
| SI-RC2-003 selection integrity | The production project prepare path uses the exported normalizer. Manifest reads verify the full fingerprint, valid selection values and agreement with top-level privacy/depth/locale. Native tools reject changed selection fields and incompatible explicit requests. |
| SI-RC2-004 analysis lifetime | A scheduler slot covers snapshot collection, Worker analysis and termination. Mixed tool/command calls measure actual live Workers; at most two run together. The 2,001st selected session is rejected before acquiring its query lease; size is checked before detached cloning. |
| SI-RC2-005 bounded reads | Compressed files are read by Zstandard block rather than whole frame. Decoding calls release at most 128 KiB of new output; windows are capped at 64 MiB. Known and unknown frame sizes, multiple frames, checksums, every truncation of the final test frame and partial long lines have regressions. File, line and header limits retain explainable refusal and no older-generation fallback. |
| SI-RC2-006 provenance | Injected `schedule` and `user-question-reply` messages remain excluded from body evidence and acceptance inference. Official recovery codes remain uncertainty rather than confirmed failure or retry authorization. |
| SI-RC2-007 output | Completed native reports use a single existing filesystem path with `--no-open`; default output includes a viewing hint. Semantic preparation still returns its orchestration message until the report exists. |

The independent repair suite adds actual Worker lifetime observations and the project preparation path, rather than inferring those results from blocked query mocks. A 32 MiB high-compression sample with a 4 KiB decoded budget allocated about 32 MiB before repair; the unknown-size replay after repair allocated about 270 KiB in Python. These are Python allocation observations, not a whole-process RSS bound.

## Gate status before artifact freeze

| Gate | Result and limit |
| --- | --- |
| S1 source/contract | 100 Node tests and 89 Python tests pass locally against the RC.2 fixture runtime. Native rules, fixture reproduction, strict session contract, repair fixtures, contract tests and actual services pass. |
| S2 CI | Exact repaired-commit cross-platform CI is required after push. Local results are separate. |
| S3 artifact | Freeze one commit-bound package with the canonical producer. Do not reuse the rejected development tarball or repackage on receiving platforms. |
| S4 macOS | Web, Headless and official Electron Desktop remain separate native gates. The ordinary npm CLI reports RC.2 and explicitly rejects managing the Desktop profile through `plugin --profile desktop`. |
| S5 Windows | Independently repeat the three host gates with the same artifact, including Chinese/space paths, installation lifecycle and loaded bytes. Hosted Windows portable acceptance cannot replace the official app. |
| S6 model/page | Nonempty real-provider batch, aggregate and finalize; invalid-output fallback; resume; Web/Desktop viewing and offline HTML interaction remain required. Synthetic semantic output is separately labelled. |
| S7 readers/consumers | Both README/CHANGELOG languages and security claims are reviewed. Separately installed CLI/Skill adoption is a later consumer gate; Bundle installation does not update them. |

The query API materializes a session before yielding its lease. Pre-clone size checks limit additional copying, but cannot cap that upstream allocation. Two Worker old-space limits do not bound total host RSS. Reports and evidence remain local until explicitly sent; redaction does not guarantee disclosure safety.

## 中文

0.6.0 的最低宿主为 DSH `>=0.2.0-rc.2`。独立复核发现并修复了项目 prepare 报错、Worker 并发限制失效、Python 先整帧展开再检查预算、恢复指纹未验证及 `--no-open` 输出前缀问题。新增回归覆盖真实生产入口与实际 Worker 生命周期；本机 100 项 Node、89 项 Python 及 RC.2 契约检查通过。

本页记录候选状态，不代表已发版。macOS 与 Windows 的 Web、Headless、官方 Desktop，真实模型和离线页面均需分别验收。官方 Desktop profile 由 Electron 应用及其正式命令 carrier 管理，不能以 npm CLI 的 Web profile 替代。Python 分配量、Worker old-space 与宿主 RSS 是不同证据；query 服务返回前的原始会话分配仍由宿主负责。

升级 Bundle 不会更新单独安装的 Python CLI/Skill。新制品必须绑定修复提交与完整文件摘要，所有平台使用同一份 tgz；原开发制品保留为被拒绝的历史证据。待验收结果由独立协调者追加，不改写已有版本的历史记录。

## Verification performed (development level, 2026-11-06 macOS, Node v25.1.0 / Python 3.12.2)

### Repair round (same day): review findings F1/F2/G1 closed

The first candidate commit `c9916c8…` was independently reviewed and returned with two semantic-evidence defects and one acceptance gap. All three are closed in the repair commit bound by this updated record; the review's two strict-valid counterexample logs are now repo fixtures, and the invalid "copy a result and rewrite its turn" test shapes from the first round were replaced with complete, catalog-admissible logs.

| Finding | Closure evidence |
| --- | --- |
| F1 — inherited calls lost their scoped identity on cancellation (Python wrote `tool=unknown, verification=false` where the native analyzer kept `bash`/`true`) | The inherited-prefix state transfer now carries `scoped_calls`/`settled_calls`/`recovery_seen`; the native prefix records the same scoped entries; the scoped lookup never impersonates a same-callId call from another turn and keeps `unknown` when no scope matches. Regression corpus: `inherited-ptc` and `inherited-outer` fixtures (official strict restore proven) plus a missing-scope negative; both runtimes' final tool facts and record identities compare exactly equal |
| F2 — final semantic batch evidence IDs collided (same tool + code in two turns hashed to one ID on both runtimes) | Evidence IDs are now built from a common canonical JSON encoding of `{family, role, session, seq, source, text}`; the call-scope source identity uses one cross-runtime encoding (`[callId, turn, step]` JSON array, replacing the Python-repr/JS-JSON mismatch). The `repeated-cancellation` fixture drives prepare → batch on both runtimes: two distinct IDs, both referencable by the facet validation consumer, fabricated references refused; identical records stay deduplicated |
| G1 — real PTC and Agent-scope execution was not covered | New repo-maintained check `scripts/dsh-executor-contract.mjs` (exit 0, wired into the CI primary lanes): the official `PtcExecutor` + `NodePtcRuntime` over the official loader composition (`scripts/rc1-executor-composition.yaml`, exact `tests/dsh-host` closure) dispatches `run_code` whose program calls `session_insights_prepare` through the generated SDK and lands a non-empty report; the official `NativeToolExecutor` dispatches the same tool directly; announced surface = admitted surface = executed surface on both executors; conditional `when:false` tools are unannounced, unexecuted; disposed toolSets and removed tools refuse; a pre-aborted call settles without side effects; a withdrawn executor selection never falls back. Per-Agent-scoped executor mounting with a model-driven Agent loop is **not** covered here (the zero-model boundary cannot construct a supported model-driven Agent) and remains with native acceptance |

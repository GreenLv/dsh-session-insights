## Dependency risk (release-blocking)

- rc.5 did not fix the upstream pin: six official packages still pin `zod@4.4.3` (GHSA-mrhx-c7xc-m3w5 / CVE-2023-54404, patched 4.6.6). The rc.5 contract-runtime closure and this project's rc.5-refreshed peer lock both resolve `zod@4.4.3`; the full rc.5 host tree resolves its top-level `zod` to 4.6.7 but keeps exact-pinned nested 4.4.3 copies.
- The 0.6.1 exception expired by its own terms (product version and dependency-cohort change) and has been removed; no new decision exists for this candidate.
- `scripts/audit_node_deps.mjs` now has three honest outcomes: `clean` (zero exit + valid non-empty inventory), `accepted_known_risk` (exact cohort-bound policy naming this one advisory), everything else fails (`failed` / `unauthorized_findings`). Network failures, invalid JSON, missing steps, cancellation and new high/critical findings cannot pass; regression tests cover each state.
- Observed on the refreshed root lock (peers at rc.5): production and full scans both report 23 affected package entries terminating at the single direct Zod advisory — one advisory propagated through dependencies, not 23 independent vulnerabilities. CI records `unauthorized_findings` and the dependency-security job fails by design until a maintainer records a new decision for this exact cohort.
- Python audit (`pip-audit` over the declared set) reports no known vulnerabilities.

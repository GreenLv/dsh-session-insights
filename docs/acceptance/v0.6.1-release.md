## Accepted upstream dependency gap

DSH rc.2/rc.3 pins `zod@4.4.3`, affected by [GHSA-mrhx-c7xc-m3w5 / CVE-2023-54404](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5). Large arrays containing many invalid elements can exhaust memory in an affected validation path. Zod 4.6.6 contains the fix; this release does not replace the upstream dependency. A reachable DSH exploit path and everyday trigger probability have not been established.

The maintainer explicitly accepted only this advisory and package version for 0.6.1 and the reviewed rc.2/rc.3 dependency cohort. Raw npm audit findings remain retained; CI blocks other high/critical findings and unsuccessful scans. Changing the release version or reviewed DSH cohort expires the exception. At the next DSH upgrade, rerun the scans and remove the exception once fixed; a new rc alone does not establish a fix. Any remaining gap requires explicit reassessment. See [SECURITY.md](../../SECURITY.md#known-upstream-dependency-gap-in-061) and the [exact exception policy](../../config/dependency-audit-exceptions.json).

## Limits of this evidence

- Desktop backend checks do not establish main-application GUI behavior.
- Windows private ACL rules were observed; cross-user access denial was not exercised.
- The full-profile missing-approval-service branch was not run. A separate real-SDK negative control verifies fail-closed behavior.
- A horizontal-overflow layout advisory remains around a 538px viewport.
- Earlier resource measurements do not establish a new full-host RSS ceiling or a saturation benchmark.
- Publication, installed payload, saved dependency request, enablement and loaded behavior are separate results. Existing consumer updates belong to their deployment records; this document does not claim daily profiles were upgraded or started.

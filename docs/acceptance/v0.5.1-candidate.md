## Recovery semantics

Only structured `data.error.code` values exactly equal to `TOOL_OUTCOME_UNKNOWN` or `TOOL_NOT_STARTED`, paired with a nonempty call ID, enter `tool_recovery: {outcome_unknown, not_started}`. Totals and session summaries expose these counters. Recovery does not add a failure, failed verification, permission block, state change or retry. Text mentioning a code, an error without a code, and ordinary codes including object-prototype names keep ordinary result rules.

Recovery evidence is bound to `(callId, turn, step)`. Reusing an ID in a later turn preserves a separate uncertainty record and does not borrow tool metadata from an earlier call. A settled call retains its result; the strict official catalog rejects a second result for the same scope. Analyzer-side defensive controls also cover late results outside that strict admission boundary. The recovery text asks readers to check external state before retrying an operation that can change data; neither code proves execution or absence of effects.

The fixture generator imports the target package's official `interruptedTurnClosers` / `ToolCallRecovery`, requires strict catalog admission and verifies that the repaired tail closes once. The retained `tests/fixtures/rc2-repairs` directory name does not promise support for the old host. Node/Python tests cover counters, ordinary-error controls, scoped semantic evidence, persisted-file parsing, repeat analysis, and three privacy modes × two locales.

## Artifact and portable gate

`scripts/pack_candidate.mjs <full-commit> <output-directory>` requires a clean checkout at that exact commit. It copies the npm file list into a private staging directory, adds `gitHead`, packs once and reads the tarball back. It retains the tarball, SHA-256, size and file inventory without editing the checkout. The Ubuntu Node 22.19.0 contract job can produce the `candidate-tgz` artifact on a candidate branch; the dispatchable `windows-host-acceptance` workflow also offers a producer mode. Select one producer result for the release and transport those exact bytes to every consumer.

`scripts/verify_host_acceptance.mjs` verifies digest and embedded identity, installs with the official CLI under a scratch `DSH_HOME`, compares the original, reinstalled and loaded package files, and registers the tools on the target services. Real Session/query services hold two populated synthetic sessions. The production project filter selects one path containing Chinese characters and spaces. Both language reports must contain one selected session, one ordinary failure and exactly one of each recovery status. A pending prepare operation is cancelled; no new run appears during the following 500 ms, then a populated rerun succeeds. This observation does not locate cancellation within a particular worker phase.

The entry emits the generic `native-acceptance/v2` schema after context disposal and scratch removal. `scripts/validate_host_annex.py` validates the complete gate set, identity bindings, status and redaction. Public annexes contain no machine-local paths. This is installed-artifact and service evidence: full profile boot, real JSONL persistence, actual Agent command execution and model calls remain separate native gates.
